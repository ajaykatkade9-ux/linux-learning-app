🧪 Linux Hands-On Labs

Build practical Linux administration and production troubleshooting skills in a controlled lab environment.

⚠️ Lab Safety Rules

  • Use a disposable VM or dedicated learning server.
  • Never run storage, LVM or network labs on production.
  • Take a VM snapshot before system-changing labs.
  • Read the complete lab and cleanup section before starting.
  • Use only the exact lab resource names shown here.
  • Verify commands and devices before destructive operations.
  • Keep console access during SSH and networking labs.
  • Run each lab in one terminal so variables remain available.
Storage and LVM commands can destroy data if the wrong device is selected. These labs use loopback image files, but you must still verify every resolved device before continuing.

Lab 1 — User Management

Objective

Create a user and group, manage group membership, inspect account files and remove the lab resources.

Pre-check

getent passwd linuxlab_user
getent group linuxlab_ops

Both commands should return no entry before continuing.

Create lab accounts

sudo groupadd linuxlab_ops

sudo useradd \
  --create-home \
  --shell /bin/bash \
  --groups linuxlab_ops \
  linuxlab_user

Inspect

id linuxlab_user
groups linuxlab_user
getent passwd linuxlab_user
getent group linuxlab_ops

sudo passwd -S linuxlab_user
sudo chage -l linuxlab_user

ls -ld /home/linuxlab_user

Test supplementary group access

sudo install \
  -d \
  -o root \
  -g linuxlab_ops \
  -m 0770 \
  /tmp/linuxlab-group-dir

sudo -u linuxlab_user \
  touch /tmp/linuxlab-group-dir/user-file

ls -la /tmp/linuxlab-group-dir

Acceptance criteria

  • User has a home directory and Bash shell.
  • User belongs to linuxlab_ops.
  • User can create a file in the group directory.

Cleanup

sudo rm -r /tmp/linuxlab-group-dir
sudo userdel --remove linuxlab_user
sudo groupdel linuxlab_ops

getent passwd linuxlab_user
getent group linuxlab_ops

Lab 3 — Process and Signal Management

Objective

Start a background process, inspect its state, stop it, continue it and terminate it gracefully.

Start a lab process

sleep 600 &
LAB_PROCESS_PID=$!

echo "$LAB_PROCESS_PID"

Inspect

ps -o pid,ppid,stat,etime,comm \
  -p "$LAB_PROCESS_PID"

cat /proc/$LAB_PROCESS_PID/status
ls -l /proc/$LAB_PROCESS_PID/fd

Send signals

kill -STOP "$LAB_PROCESS_PID"

ps -o pid,stat,comm \
  -p "$LAB_PROCESS_PID"

kill -CONT "$LAB_PROCESS_PID"

ps -o pid,stat,comm \
  -p "$LAB_PROCESS_PID"

kill -TERM "$LAB_PROCESS_PID"
wait "$LAB_PROCESS_PID"

Acceptance criteria

  • Stopped process shows a state containing T.
  • Continued process returns to a sleeping state.
  • SIGTERM removes the process cleanly.

Lab 4 — systemd Service

Objective

Create, start, inspect and safely remove a custom service.

Run this only on a disposable VM. It creates one exact unit: /etc/systemd/system/linuxlab-demo.service.

Create the unit

sudo nano \
  /etc/systemd/system/linuxlab-demo.service

Paste:

[Unit]
Description=Linux Course Lab Service
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/sleep infinity
Restart=on-failure
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true

[Install]
WantedBy=multi-user.target

Validate and start

sudo systemd-analyze verify \
  /etc/systemd/system/linuxlab-demo.service

sudo systemctl daemon-reload
sudo systemctl start linuxlab-demo.service

systemctl status \
  linuxlab-demo.service \
  --no-pager -l

Inspect process, unit and logs

systemctl show \
  linuxlab-demo.service \
  -p MainPID \
  -p ActiveState \
  -p SubState \
  -p ExecMainStatus

systemctl cat linuxlab-demo.service

journalctl \
  -u linuxlab-demo.service \
  --since "10 minutes ago"

Cleanup

sudo systemctl stop \
  linuxlab-demo.service

sudo rm \
  /etc/systemd/system/linuxlab-demo.service

sudo systemctl daemon-reload
sudo systemctl reset-failed

systemctl status \
  linuxlab-demo.service

The final status should report that the unit cannot be found.

Lab 5 — Storage and Filesystem

Objective

Create a file-backed block device, format it, mount it, write data and cleanly detach it.

Keep this entire lab in one terminal. Confirm that LAB_STORAGE_LOOP contains a /dev/loop device before formatting.

Create the loopback disk

truncate \
  -s 256M \
  /tmp/linux-course-storage.img

LAB_STORAGE_LOOP=$(
  sudo losetup \
    --find \
    --show \
    /tmp/linux-course-storage.img
)

echo "$LAB_STORAGE_LOOP"

sudo losetup \
  --list \
  | grep linux-course-storage.img

Validate before formatting

case "$LAB_STORAGE_LOOP" in
  /dev/loop[0-9]*)
    echo "Validated: $LAB_STORAGE_LOOP"
    ;;
  *)
    echo "STOP: unexpected device"
    false
    ;;
esac

Format and mount

sudo mkfs.ext4 \
  -L linuxlab_storage \
  "$LAB_STORAGE_LOOP"

sudo mkdir -p \
  /mnt/linux-course-storage

sudo mount \
  "$LAB_STORAGE_LOOP" \
  /mnt/linux-course-storage

Verify and write

findmnt \
  /mnt/linux-course-storage

lsblk -f "$LAB_STORAGE_LOOP"

df -hT \
  /mnt/linux-course-storage

echo "storage lab successful" \
  | sudo tee \
    /mnt/linux-course-storage/result.txt

cat \
  /mnt/linux-course-storage/result.txt

Cleanup

sudo umount \
  /mnt/linux-course-storage

sudo rmdir \
  /mnt/linux-course-storage

sudo losetup \
  --detach \
  "$LAB_STORAGE_LOOP"

rm \
  /tmp/linux-course-storage.img

Lab 6 — LVM

Objective

Create a PV, VG and LV using a disposable loopback image, format it, extend it and remove every lab resource.

This lab contains destructive LVM commands. Use only the loop device resolved from /tmp/linux-course-lvm.img. Never substitute a real disk.

Pre-check exact lab names

sudo vgs linuxlab_vg
test -e /tmp/linux-course-lvm.img \
  && echo "STOP: image already exists"

The VG lookup should report that linuxlab_vg does not exist.

Create disposable device

truncate \
  -s 512M \
  /tmp/linux-course-lvm.img

LAB_LVM_LOOP=$(
  sudo losetup \
    --find \
    --show \
    /tmp/linux-course-lvm.img
)

echo "$LAB_LVM_LOOP"

case "$LAB_LVM_LOOP" in
  /dev/loop[0-9]*)
    echo "Validated: $LAB_LVM_LOOP"
    ;;
  *)
    echo "STOP: unexpected device"
    false
    ;;
esac

Create LVM structure

sudo pvcreate "$LAB_LVM_LOOP"

sudo vgcreate \
  linuxlab_vg \
  "$LAB_LVM_LOOP"

sudo lvcreate \
  --name linuxlab_lv \
  --size 200M \
  linuxlab_vg

Inspect

sudo pvs
sudo vgs
sudo lvs

sudo pvdisplay "$LAB_LVM_LOOP"
sudo vgdisplay linuxlab_vg
sudo lvdisplay \
  /dev/linuxlab_vg/linuxlab_lv

Format and mount

sudo mkfs.ext4 \
  /dev/linuxlab_vg/linuxlab_lv

sudo mkdir -p \
  /mnt/linux-course-lvm

sudo mount \
  /dev/linuxlab_vg/linuxlab_lv \
  /mnt/linux-course-lvm

df -hT \
  /mnt/linux-course-lvm

Extend by 100 MiB

sudo lvextend \
  --size +100M \
  --resizefs \
  /dev/linuxlab_vg/linuxlab_lv

sudo lvs
df -hT \
  /mnt/linux-course-lvm

Cleanup in exact order

sudo umount \
  /mnt/linux-course-lvm

sudo rmdir \
  /mnt/linux-course-lvm

sudo lvremove \
  --yes \
  /dev/linuxlab_vg/linuxlab_lv

sudo vgremove \
  --yes \
  linuxlab_vg

sudo pvremove \
  --yes \
  "$LAB_LVM_LOOP"

sudo losetup \
  --detach \
  "$LAB_LVM_LOOP"

rm \
  /tmp/linux-course-lvm.img

Lab 7 — Network Namespace

Objective

Connect the host to an isolated network namespace using a virtual Ethernet pair.

Pre-check

ip netns list
ip link show llab-host

linuxlab_ns and llab-host should not exist.

Create the namespace and veth pair

sudo ip netns add linuxlab_ns

sudo ip link add \
  llab-host \
  type veth \
  peer name llab-ns

sudo ip link set \
  llab-ns \
  netns linuxlab_ns

Configure addresses

sudo ip address add \
  10.200.1.1/24 \
  dev llab-host

sudo ip link set \
  llab-host up

sudo ip netns exec \
  linuxlab_ns \
  ip address add \
  10.200.1.2/24 \
  dev llab-ns

sudo ip netns exec \
  linuxlab_ns \
  ip link set llab-ns up

sudo ip netns exec \
  linuxlab_ns \
  ip link set lo up

Verify connectivity

ip address show llab-host

sudo ip netns exec \
  linuxlab_ns \
  ip address

ping -c 3 \
  10.200.1.2

sudo ip netns exec \
  linuxlab_ns \
  ping -c 3 \
  10.200.1.1

Run an isolated web server

sudo ip netns exec \
  linuxlab_ns \
  python3 -m http.server \
  8080 \
  --bind 10.200.1.2 &

LAB_HTTP_PID=$!

sleep 2

curl \
  http://10.200.1.2:8080

sudo kill \
  "$LAB_HTTP_PID"

Cleanup

sudo ip netns delete \
  linuxlab_ns

sudo ip link delete \
  llab-host \
  2>/dev/null || true

ip netns list
ip link show llab-host

Lab 8 — DNS Investigation

Objective

Compare NSS, the configured resolver and direct DNS queries.

Inspect configuration

cat /etc/resolv.conf
grep '^hosts:' /etc/nsswitch.conf
resolvectl status

Resolve through the operating system

getent ahosts example.com
getent hosts localhost

Query DNS directly

dig example.com
dig A example.com
dig AAAA example.com
dig +short example.com

dig @1.1.1.1 example.com
dig +trace example.com

Acceptance criteria

  • Explain which resolver is configured.
  • Identify A and AAAA answers.
  • Explain why getent and dig may differ.
  • Separate DNS failure from general network failure.
Direct public DNS queries may be blocked by enterprise or restricted lab networks. That result is itself useful evidence.

Lab 9 — SSH Key Authentication

Objective

Create a dedicated lab account, authorize an Ed25519 key, test localhost login and clean up.

Keep any existing administrator session open. Do not change sshd_config for this lab.

Verify SSH service

sudo sshd -t
sudo systemctl status ssh sshd
sudo ss -ltnp | grep ':22'

Create the test account and key

sudo useradd \
  --create-home \
  --user-group \
  --shell /bin/bash \
  linuxlab_ssh

ssh-keygen \
  -t ed25519 \
  -N '' \
  -f /tmp/linux-course-ssh-key

Install the public key

sudo install \
  -d \
  -o linuxlab_ssh \
  -g linuxlab_ssh \
  -m 0700 \
  /home/linuxlab_ssh/.ssh

sudo cp \
  /tmp/linux-course-ssh-key.pub \
  /home/linuxlab_ssh/.ssh/authorized_keys

sudo chown \
  linuxlab_ssh:linuxlab_ssh \
  /home/linuxlab_ssh/.ssh/authorized_keys

sudo chmod \
  0600 \
  /home/linuxlab_ssh/.ssh/authorized_keys

sudo restorecon \
  -Rv \
  /home/linuxlab_ssh/.ssh \
  2>/dev/null || true

Verify permissions

namei -l \
  /home/linuxlab_ssh/.ssh/authorized_keys

Test login

ssh \
  -i /tmp/linux-course-ssh-key \
  -o StrictHostKeyChecking=accept-new \
  -o UserKnownHostsFile=/tmp/linux-course-known-hosts \
  linuxlab_ssh@localhost \
  'id && hostname'

Cleanup

sudo userdel \
  --remove \
  linuxlab_ssh

sudo groupdel \
  linuxlab_ssh \
  2>/dev/null || true

rm \
  /tmp/linux-course-ssh-key \
  /tmp/linux-course-ssh-key.pub \
  /tmp/linux-course-known-hosts

Lab 10 — Production Bash Script

Objective

Build a strict Bash health-check script with arguments, validation, useful output and exit codes.

Create the script

nano /tmp/linux-course-health.sh

Paste:

#!/usr/bin/env bash

set -Eeuo pipefail

readonly CHECK_PATH="${1:-/}"
readonly DISK_LIMIT="${2:-80}"

log() {
  printf '%s %s\n' \
    "$(date --iso-8601=seconds)" \
    "$*"
}

fail() {
  log "ERROR: $*"
  exit 1
}

[[ "$DISK_LIMIT" =~ ^[0-9]+$ ]] \
  || fail "Disk limit must be numeric"

(( DISK_LIMIT >= 1 && DISK_LIMIT <= 100 )) \
  || fail "Disk limit must be 1-100"

[[ -e "$CHECK_PATH" ]] \
  || fail "Path does not exist: $CHECK_PATH"

disk_used=$(
  df -P "$CHECK_PATH" \
    | awk '
      NR == 2 {
        gsub(/%/, "", $5)
        print $5
      }
    '
)

log "Host: $(hostname)"
log "Load: $(cut -d " " -f 1-3 /proc/loadavg)"
log "Disk usage for $CHECK_PATH: ${disk_used}%"

free -h

if (( disk_used >= DISK_LIMIT )); then
  fail "Disk usage crossed ${DISK_LIMIT}%"
fi

log "Health check passed"

Validate and run

chmod 0755 \
  /tmp/linux-course-health.sh

bash -n \
  /tmp/linux-course-health.sh

command -v shellcheck \
  && shellcheck \
    /tmp/linux-course-health.sh

/tmp/linux-course-health.sh

/tmp/linux-course-health.sh \
  / \
  95

Test the failure path

/tmp/linux-course-health.sh \
  / \
  1

echo "$?"

Exit code 1 is expected when actual disk usage is at least 1%.

Cleanup

rm \
  /tmp/linux-course-health.sh

Lab 11 — Performance Troubleshooting

Objective

Capture a baseline, generate controlled CPU and I/O activity and identify the responsible process.

Baseline

uptime
free -h
df -hT
vmstat 1 5
iostat -xz 1 5

Controlled CPU activity

timeout 20 \
  yes \
  >/dev/null &

LAB_CPU_PID=$!

ps -o pid,ppid,stat,pcpu,pmem,comm \
  -p "$LAB_CPU_PID"

top -b -n 1 \
  | head -20

pidstat -u \
  -p "$LAB_CPU_PID" \
  1 5

wait "$LAB_CPU_PID" || true

Controlled file I/O

dd \
  if=/dev/zero \
  of=/tmp/linux-course-io.test \
  bs=1M \
  count=256 \
  conv=fdatasync \
  status=progress

iostat -xz 1 5

rm \
  /tmp/linux-course-io.test

Acceptance criteria

  • Identify the CPU-consuming PID.
  • Explain user, system, I/O wait and idle CPU.
  • Identify the active block device.
  • Compare baseline and test measurements.

Lab 12 — Production Incident Simulations

Incident A — Port conflict

python3 -m http.server \
  18080 \
  --bind 127.0.0.1 &

LAB_SERVER_PID=$!

sleep 2

python3 -m http.server \
  18080 \
  --bind 127.0.0.1

The second server should fail because the address is already in use. 

sudo ss -ltnp \
  'sport = :18080'

curl \
  http://127.0.0.1:18080

kill -TERM \
  "$LAB_SERVER_PID"

wait \
  "$LAB_SERVER_PID"

Incident B — Deleted-open file

python3 -c '
import os
import time

path = "/tmp/linuxlab-deleted.log"

with open(path, "wb") as file:
    file.write(b"x" * 50 * 1024 * 1024)
    file.flush()
    os.fsync(file.fileno())
    time.sleep(300)
' &

LAB_DELETED_PID=$!

sleep 2

rm \
  /tmp/linuxlab-deleted.log

sudo lsof +L1 \
  | grep linuxlab-deleted

kill -TERM \
  "$LAB_DELETED_PID"

wait \
  "$LAB_DELETED_PID" \
  2>/dev/null || true

sudo systemd-run \

Incident D — Layered connectivity diagnosis

getent ahosts example.com
ip route get 1.1.1.1

Explain which layer each command tests:
