🧬 Advanced Linux Internals

Understand how processes communicate with the kernel, how Linux exposes runtime information, how containers isolate workloads and how to troubleshoot resource limits.

⚡ 60-Second Revision

  • /proc exposes process and kernel runtime information.
  • /sys exposes kernel objects, devices and drivers.
  • Applications enter the kernel using system calls.
  • A file descriptor identifies an open kernel-managed resource.
  • ulimit controls per-process resource limits.
  • Kernel modules extend a running kernel.
  • Namespaces isolate what processes can see.
  • cgroups control and account for resource usage.
  • Capabilities divide root privileges into smaller privileges.
  • Signals notify or control processes.
  • Sockets provide local or network communication.
  • Containers combine namespaces, cgroups and security controls.

1. User Space and Kernel Space

Area Purpose Examples
User space Runs applications with restricted access Bash, Nginx, Python, Docker CLI
Kernel space Controls hardware and protected resources Scheduler, memory manager, networking, drivers
System-call interface Controlled entry from applications into the kernel open, read, write, fork, execve, socket

Inspect the running kernel:

uname -a
uname -r
cat /proc/version
cat /proc/cmdline
dmesg | head
Applications normally do not access hardware directly. They request kernel operations using system calls.

2. The /proc Filesystem

/proc is a virtual filesystem. Most entries are generated dynamically by the kernel instead of being stored as normal disk files. 

mount | grep ' on /proc '
findmnt /proc
ls /proc | head
cat /proc/filesystems

Important system-wide files

Path Information
/proc/cpuinfo CPU information
/proc/meminfo Memory statistics
/proc/loadavg Load average and runnable tasks
/proc/uptime System uptime and idle time
/proc/mounts Current mount information
/proc/interrupts Interrupt activity by CPU
/proc/modules Loaded kernel modules
/proc/sys Runtime kernel parameters 
cat /proc/cpuinfo
cat /proc/meminfo
cat /proc/loadavg
cat /proc/uptime
cat /proc/interrupts
cat /proc/modules

3. Process Information Inside /proc

Every visible process normally has a directory named /proc/PID. 

PID=$$

ls /proc/$PID
cat /proc/$PID/status
cat /proc/$PID/comm
tr '\0' ' ' < /proc/$PID/cmdline
readlink /proc/$PID/exe
readlink /proc/$PID/cwd
Path Purpose
/proc/PID/status Identity, memory, capabilities and process state
/proc/PID/cmdline Original process arguments
/proc/PID/environ Process environment
/proc/PID/fd Open file descriptors
/proc/PID/limits Resource limits
/proc/PID/maps Virtual memory mappings
/proc/PID/io Process I/O counters
/proc/PID/ns Namespace membership
/proc/PID/cgroup Control-group membership 
PID=$$

ls -l /proc/$PID/fd
cat /proc/$PID/limits
cat /proc/$PID/maps
cat /proc/$PID/io
ls -l /proc/$PID/ns
cat /proc/$PID/cgroup
Process environment variables can contain secrets. Do not copy /proc/PID/environ into tickets, chat or public logs.

4. Kernel Parameters and sysctl

Files under /proc/sys expose configurable runtime kernel parameters. The sysctl command provides a safer readable interface. 

sysctl kernel.hostname
sysctl vm.swappiness
sysctl fs.file-max
sysctl net.ipv4.ip_forward

Equivalent paths:

cat /proc/sys/kernel/hostname
cat /proc/sys/vm/swappiness
cat /proc/sys/fs/file-max
cat /proc/sys/net/ipv4/ip_forward

Persistent custom settings usually belong under:

/etc/sysctl.d/*.conf

Validate and load configured values:

sudo sysctl --system
Do not copy random sysctl tuning values into production. Network, memory and filesystem settings can reduce stability or break containers, VPNs and routing.

5. The /sys Filesystem

/sys, also called sysfs, exposes kernel objects, devices, drivers, buses and their relationships. 

findmnt /sys
ls /sys
ls /sys/class
ls /sys/block
ls /sys/bus
ls /sys/devices
ls /sys/module
Path Purpose
/sys/class Devices grouped by class
/sys/block Block devices
/sys/bus Hardware buses and drivers
/sys/devices Kernel device hierarchy
/sys/module Loaded module information
/sys/fs/cgroup cgroup hierarchy

Network-device example

ls /sys/class/net

for interface in /sys/class/net/*; do
  echo "$interface"
  cat "$interface/operstate"
done

Block-device example

lsblk
ls -l /sys/block
cat /sys/block/*/queue/scheduler 2>/dev/null
Some sysfs files are writable control interfaces. Writing an incorrect value can change device or kernel behaviour immediately.

6. System Calls

System calls are the formal interface through which user-space programs request kernel operations.

Category Examples
Files openat, read, write, close, stat
Processes clone, fork, execve, wait4, exit
Memory mmap, munmap, brk, mprotect
Networking socket, bind, listen, accept, connect
Signals kill, rt_sigaction, rt_sigprocmask

Trace system calls:

strace true
strace -o /tmp/ls.trace ls /tmp
less /tmp/ls.trace

Trace selected calls:

strace -e trace=openat,read,write,close \
  ls /tmp

Attach to an existing process:

sudo strace -p PID

Summarize system-call activity:

strace -c ls /usr
Attaching tracing tools can affect performance and expose application data. Use production change and access procedures.

7. File Descriptors

A file descriptor is a small integer used by a process to refer to a kernel-managed open resource.

Descriptor Standard name
0 Standard input
1 Standard output
2 Standard error

Files, directories, sockets, pipes, terminals and event interfaces can all be represented by file descriptors. 

ls -l /proc/$$/fd
lsof -p $$
lsof -p PID
sudo lsof +L1

Shell redirection

command > output.log
command 2> error.log
command > all.log 2>&1
command >> output.log
command < input.txt

Count descriptors used by a process

find /proc/PID/fd -maxdepth 1 \
  -type l 2>/dev/null | wc -l

System-wide file-handle information

cat /proc/sys/fs/file-nr
sysctl fs.file-max

8. ulimit and Resource Limits

Resource limits protect the system from excessive resource consumption by a process or user. 

ulimit -a
ulimit -Sn
ulimit -Hn
cat /proc/$$/limits
prlimit --pid $$
Limit Meaning
nofile Maximum open file descriptors
nproc Maximum processes or threads
core Core-dump size
stack Thread stack size
memlock Memory that may be locked

Traditional login-session configuration:

/etc/security/limits.conf
/etc/security/limits.d/*.conf

systemd service limits:

systemctl show SERVICE_NAME \
  -p LimitNOFILE \
  -p LimitNPROC

systemctl cat SERVICE_NAME

Example systemd override:

[Service]
LimitNOFILE=65535
Changing ulimit in an interactive shell does not automatically change limits for an existing systemd service.

9. Kernel Modules

A loadable kernel module adds functionality such as a device driver or filesystem without rebuilding the entire kernel. 

lsmod
cat /proc/modules
modinfo MODULE_NAME
find /lib/modules/$(uname -r) -type f | head

Module dependency information:

sudo depmod -a
modprobe --show-depends MODULE_NAME

Load and remove modules:

sudo modprobe MODULE_NAME
sudo modprobe -r MODULE_NAME

Inspect kernel messages:

sudo dmesg -T | tail -100
sudo journalctl -k --since today

Inspect module parameters:

ls /sys/module/MODULE_NAME/parameters
modinfo -p MODULE_NAME

Check kernel taint state:

cat /proc/sys/kernel/tainted
Removing a module used by storage, networking or another critical component can crash or disconnect the system. Never experiment with production modules without a recovery plan.

10. Linux Namespaces

Namespaces isolate the view of system resources for a process.

Namespace Isolates
mnt Mount points
pid Process IDs
net Interfaces, routes, ports and firewall state
uts Hostname and domain name
ipc System V IPC and POSIX message queues
user User and group ID mappings
cgroup View of cgroup hierarchy
time Selected system clocks

Inspect namespace membership:

lsns
ls -l /proc/$$/ns
ls -l /proc/PID/ns
readlink /proc/PID/ns/pid
readlink /proc/PID/ns/net

Compare two processes:

readlink /proc/PID_ONE/ns/net
readlink /proc/PID_TWO/ns/net

Run a command in another process namespace:

sudo nsenter \
  --target PID \
  --mount \
  --uts \
  --ipc \
  --net \
  --pid

Create a temporary PID namespace lab:

sudo unshare \
  --fork \
  --pid \
  --mount-proc \
  bash

ps -ef
exit
Namespace isolation changes what a process can see. It does not automatically enforce resource limits.

11. cgroups

Control groups organize processes and provide resource accounting, limits and prioritization.

Detect the cgroup filesystem:

findmnt /sys/fs/cgroup
stat -fc %T /sys/fs/cgroup
cat /proc/$$/cgroup

Output cgroup2fs indicates a unified cgroup v2 hierarchy. 

cat /sys/fs/cgroup/cgroup.controllers
systemd-cgls
systemd-cgtop

Important cgroup v2 files

File Purpose
cgroup.procs Processes inside the cgroup
cpu.max CPU quota
cpu.weight Relative CPU weight
memory.current Current memory usage
memory.max Hard memory limit
memory.events Memory pressure and OOM events
pids.current Current process count
pids.max Process-count limit
io.stat I/O statistics

Inspect a systemd service cgroup:

systemctl show SERVICE_NAME \
  -p ControlGroup \
  -p MemoryCurrent \
  -p MemoryMax \
  -p CPUQuotaPerSecUSec \
  -p TasksCurrent \
  -p TasksMax

Create a temporary systemd scope:

systemd-run --user \
  --scope \
  -p MemoryMax=200M \
  -p TasksMax=50 \
  bash
Directly editing cgroup files can disrupt workloads. On systemd-based production servers, manage service resources through systemd unit settings when practical.

12. Linux Capabilities

Capabilities divide traditional root authority into smaller independently assignable privileges. 

capsh --print
getcap /path/to/binary
sudo getcap -r / 2>/dev/null
getpcaps PID

Inspect capability masks:

grep '^Cap' /proc/$$/status
Set Meaning
CapInh Inheritable set
CapPrm Permitted set
CapEff Effective set
CapBnd Bounding set
CapAmb Ambient set

Decode a mask:

capsh --decode=CAPABILITY_HEX_VALUE

Example file capability:

sudo setcap \
  cap_net_bind_service=+ep \
  /path/to/binary

getcap /path/to/binary

sudo setcap -r /path/to/binary
Capabilities remain powerful privileges. Grant only the exact capability required by the workload.

13. Linux Signals

Signals are asynchronous notifications delivered to a process or thread. 

kill -l
ps -o pid,ppid,stat,comm -p PID
Signal Number Common purpose
SIGHUP 1 Terminal hangup or configuration reload
SIGINT 2 Interactive interrupt, usually Ctrl+C
SIGTERM 15 Request graceful termination
SIGKILL 9 Immediate kernel termination
SIGSTOP 19 Stop process execution
SIGCONT 18 Continue a stopped process
SIGCHLD 17 Child process changed state 
kill -TERM PID
kill -HUP PID
kill -STOP PID
kill -CONT PID
Signal numbers can differ by architecture. Prefer symbolic names such as kill -TERM in scripts.
SIGKILL cannot be caught or handled, so the process cannot perform cleanup. Use SIGTERM first and investigate why graceful shutdown failed.

14. Sockets

Sockets provide communication between processes on the same host or across a network.

Socket type Purpose
TCP Reliable connection-oriented network communication
UDP Connectionless datagram communication
Unix domain Local process-to-process communication
Raw Low-level protocol access 
sudo ss -lntup
ss -tan
ss -uan
ss -xap
sudo lsof -i
sudo lsof -U

Inspect a specific port:

sudo ss -ltnp 'sport = :PORT'
sudo lsof -i :PORT

Inspect socket statistics:

ss -s
cat /proc/net/sockstat
cat /proc/net/sockstat6

Important TCP states:

  • LISTEN: waiting for new connections
  • ESTABLISHED: active connection
  • TIME-WAIT: recently closed connection
  • CLOSE-WAIT: peer closed, local process has not closed
  • SYN-SENT: connection request sent
  • SYN-RECV: connection request received

16. Process Isolation

Linux process isolation commonly combines:

  • Namespaces for visibility isolation
  • cgroups for accounting and resource limits
  • Capabilities for reduced privileges
  • seccomp for system-call filtering
  • SELinux or AppArmor for mandatory access control
  • Filesystem permissions and read-only mounts
  • systemd sandboxing directives

Inspect a process:

PID=PROCESS_ID

ls -l /proc/$PID/ns
cat /proc/$PID/cgroup
grep '^Cap' /proc/$PID/status
grep '^Seccomp' /proc/$PID/status
cat /proc/$PID/limits

Check Linux Security Modules:

cat /sys/kernel/security/lsm 2>/dev/null
No single isolation feature creates a secure sandbox. Production isolation uses multiple controls together.

17. Container Internals

A Linux container is an isolated group of ordinary Linux processes. It does not require a separate guest kernel.

Container feature Linux mechanism
Separate process view PID namespace
Separate network stack Network namespace
Separate filesystem view Mount namespace and container root filesystem
Resource limits cgroups
Reduced root privileges Capabilities and user namespaces
System-call restrictions seccomp
Mandatory access control SELinux or AppArmor
Layered image filesystem OverlayFS or another storage driver

Inspect a container process from the host:

docker inspect \
  --format '{{.State.Pid}}' \
  CONTAINER_NAME

podman inspect \
  --format '{{.State.Pid}}' \
  CONTAINER_NAME

After obtaining the host PID:

PID=HOST_PROCESS_ID

ps -fp $PID
ls -l /proc/$PID/ns
cat /proc/$PID/cgroup
grep '^Cap' /proc/$PID/status
grep '^Seccomp' /proc/$PID/status
sudo nsenter -t $PID -n ip address
Root inside a container is not automatically harmless. Container security depends on capabilities, mounts, namespaces, runtime settings and host-kernel security.

19. Production Scenario — Too Many Open Files

Typical error:

Too many open files
EMFILE
ENFILE
  1. Identify the affected process.
  2. Check its soft and hard limits.
  3. Count current descriptors.
  4. Identify descriptor types.
  5. Check whether usage continuously increases.
  6. Fix the leak before increasing the limit.
cat /proc/PID/limits

find /proc/PID/fd \
  -maxdepth 1 \
  -type l 2>/dev/null | wc -l

sudo lsof -p PID
cat /proc/sys/fs/file-nr

systemctl show SERVICE_NAME \
  -p LimitNOFILE
Increasing the limit may delay failure but does not repair a file-descriptor leak.

20. Production Scenario — Container OOM

  1. Identify the container or service cgroup.
  2. Check current and maximum memory.
  3. Inspect memory event counters.
  4. Check kernel OOM logs.
  5. Determine whether the cause is a leak, spike or incorrect limit.
cat /proc/PID/cgroup

systemctl show SERVICE_NAME \
  -p ControlGroup \
  -p MemoryCurrent \
  -p MemoryMax

sudo journalctl -k \
  | grep -Ei 'oom|out of memory|killed process'

For the relevant cgroup v2 directory:

cat memory.current
cat memory.max
cat memory.events
cat memory.stat

21. Production Scenario — Process Will Not Stop

kill -TERM PID
ps -o pid,ppid,stat,wchan:30,comm -p PID
cat /proc/PID/status
sudo strace -p PID
sudo lsof -p PID
sudo journalctl _PID=PID

Process-state clues:

  • R: running or runnable
  • S: interruptible sleep
  • D: uninterruptible sleep, commonly waiting on I/O
  • T: stopped
  • Z: zombie waiting for its parent to reap it
SIGKILL does not instantly remove a process blocked in uninterruptible kernel sleep. Investigate the underlying I/O, storage, network filesystem or device problem.

22. Production Scenario — Unexpected Socket Growth

ss -s
ss -tan
sudo ss -lntup
cat /proc/net/sockstat
sudo lsof -p PID | grep -i socket

Count TCP states:

ss -tan \
  | awk 'NR>1 {count[$1]++}
         END {
           for (state in count)
             print state, count[state]
         }'
  • Many CLOSE-WAIT sockets may indicate an application close leak.
  • Many TIME-WAIT sockets may reflect high connection turnover.
  • Many SYN-RECV sockets may indicate backlog pressure or attack traffic.
  • Confirm application behaviour before changing kernel tuning.

🎯 Interview Questions

What is the difference between /proc and /sys?

/proc mainly exposes process and kernel runtime information. /sys represents kernel objects, devices, drivers and their relationships.

What is a system call?

It is a controlled interface used by a user-space program to request an operation from the kernel.

What is a file descriptor?

It is a per-process integer that refers to an open kernel-managed resource such as a file, socket or pipe.

Soft limit vs hard limit?

A process can usually lower its soft limit and raise it up to the hard limit. Raising the hard limit requires suitable privilege.

Namespace vs cgroup?

A namespace isolates what a process can see. A cgroup tracks and controls how many resources a group of processes can use.

What are Linux capabilities?

They divide the traditional all-powerful root privilege into smaller, separately assignable privileges.

Why does a zombie process exist?

The process has exited, but its parent has not yet collected its exit status using a wait operation.

Why might kill -9 appear not to work?

The process may be blocked in uninterruptible kernel sleep, or it may already be a zombie that must be reaped by its parent.

How does a container work?

It runs normal host-kernel processes using namespaces for isolation, cgroups for resource control and security mechanisms such as capabilities, seccomp and mandatory access control.

✅ Production Checklist

  • Understand which process owns the affected resource.
  • Check process status, limits, descriptors and cgroup.
  • Inspect kernel logs before changing kernel settings.
  • Measure resource usage before tuning limits.
  • Use SIGTERM before SIGKILL.
  • Do not remove critical kernel modules remotely.
  • Use systemd to manage service resource limits.
  • Combine namespaces with security controls.
  • Apply least privilege to container capabilities.
  • Test sysctl and cgroup changes before production.
  • Document why every low-level tuning change is required.
