1. Documentation Priority

Priority Source Use
1 Installed manual and package documentation Matches the installed command version
2 Distribution documentation Matches packaging and configuration layout
3 Upstream project documentation Explains the original feature and behaviour

4. How to Read Documentation Effectively

  1. Identify the exact command and installed version.
  2. Read the synopsis to understand argument order.
  3. Read descriptions before copying examples.
  4. Check defaults and distribution-specific behaviour.
  5. Read warnings, exit status and related files.
  6. Open the “See Also” references.
  7. Test commands in a disposable lab.
  8. Record verified production examples in a runbook.
Documentation examples can still change system state. Understand placeholders and exact targets before running them.

5. Documentation Practice

Use only documentation to answer:

  1. Which signal does kill send by default?
  2. What is the difference between find -mtime and -mmin?
  3. Which file configures persistent mounts?
  4. How does systemd represent a mount path as a unit name?
  5. Which SSH option disables direct root login?
  6. What does memory.max mean in cgroup v2?
  7. Which capability permits binding a privileged port?
  8. How do you inspect the route selected for one IP?

Start with:

man kill
man find
man fstab
man systemd.mount
man sshd_config
man 7 capabilities
man ip-route
