APT, dpkg, DNF/YUM, RPM, repositories, dependencies, package versions, updates and production troubleshooting.

Two common Linux families:

  • Debian / Ubuntu: apt + dpkg
  • RHEL / Rocky / Alma: dnf/yum + rpm

1. What Is a Package?

A package contains software plus metadata needed to install and manage that software.

Metadata can include:

  • Package name
  • Version
  • Architecture
  • Dependencies
  • Files
  • Installation scripts

2. Package Repository

A repository is a trusted source from which package managers retrieve package metadata and software.

On Ubuntu, inspect repository configuration:

cat /etc/apt/sources.list 2>/dev/null

ls /etc/apt/sources.list.d/

3. apt update

apt update

This refreshes local package metadata from configured repositories.

It does not mean every installed package is upgraded.

4. Search and Inspect Packages

apt search nginx

apt show nginx

apt-cache policy nginx

apt-cache policy is especially useful for checking candidate versions and package sources.

5. Installing Packages

apt install PACKAGE
Example: 
apt install curl

The package manager resolves required dependencies before installation.

6. Removing Packages

apt remove PACKAGE
Remove package configuration too: 
apt purge PACKAGE
Remove dependencies no longer needed: 
apt autoremove

7. Upgrading Packages

apt update

apt upgrade

Production upgrades should be planned carefully because package updates can change application or service behavior.

8. dpkg

dpkg is a lower-level Debian package management tool.

List installed packages: 
dpkg -l
Check a package: 
dpkg -l | grep PACKAGE
List files installed by a package: 
dpkg -L PACKAGE
Find which package owns a file: 
dpkg -S /path/to/file

9. apt vs dpkg

apt

  • Works with repositories
  • Resolves dependencies
  • Higher-level package management

dpkg

  • Lower-level package database/tool
  • Works directly with Debian packages
  • Does not perform repository dependency resolution in the same way

10. RHEL Package Management

Common commands:

dnf search PACKAGE

dnf info PACKAGE

dnf install PACKAGE

dnf remove PACKAGE

dnf upgrade

Older systems may use yum.

11. RPM

List installed packages: 
rpm -qa
Inspect package: 
rpm -qi PACKAGE
List package files: 
rpm -ql PACKAGE
Find package owning a file: 
rpm -qf /path/to/file

12. dnf vs rpm

dnf

  • Repository-aware
  • Dependency resolution
  • Higher-level package management

rpm

  • Lower-level RPM package management
  • Package database inspection
  • Direct package operations

13. Package Dependencies

Applications often require libraries or other packages. Package managers normally resolve those dependencies automatically.

On Ubuntu: 
apt-cache depends PACKAGE
Reverse dependencies: 
apt-cache rdepends PACKAGE

14. Package Versions

Installed version: 
dpkg -l | grep PACKAGE
Available versions: 
apt-cache policy PACKAGE
RHEL-style: 
dnf list installed PACKAGE

dnf info PACKAGE

15. Architecture

Check system architecture: 
uname -m

dpkg --print-architecture

Package architecture mismatches can cause installation problems.

16. Repository Connectivity

Package installation depends on repository accessibility.

Check: 
apt update
Then investigate networking if required: 
ip route

getent hosts archive.ubuntu.com

curl -I https://archive.ubuntu.com/

17. Package Database

Installed package state is maintained in a local package database.

On Debian/Ubuntu: 
dpkg -l
On RPM systems: 
rpm -qa

18. Services After Package Installation

Some packages install or start systemd services.

After installing software, inspect: 
systemctl status SERVICE_NAME

systemctl is-enabled SERVICE_NAME

ss -ltnp

🔥 Production Scenario 1 — Package Not Found

You run:

apt install PACKAGE
and receive a package-not-found error. Check: 
apt update

apt search PACKAGE

apt-cache policy PACKAGE

cat /etc/apt/sources.list 2>/dev/null

ls /etc/apt/sources.list.d/

Possible causes:

  • Package metadata is stale
  • Repository missing
  • Wrong package name
  • Package unavailable for that OS version
  • Repository disabled

🔥 Production Scenario 2 — apt update Fails

apt update
Then investigate: 
ip route

getent hosts archive.ubuntu.com

cat /etc/resolv.conf

df -h

Possible causes:

  • DNS failure
  • No network route
  • Repository unavailable
  • Invalid repository configuration
  • Disk full
  • Certificate/time-related issues

🔥 Production Scenario 3 — Dependency Problem

A package installation fails because dependencies cannot be satisfied.

Inspect: 
apt-cache policy PACKAGE

apt-cache depends PACKAGE

dpkg -l

Check whether repositories, package versions and OS release are compatible.

🔥 Production Scenario 4 — Works Before Upgrade, Fails After

An application stops working after package updates.

Investigate: 
grep -i "upgrade" /var/log/dpkg.log 2>/dev/null

systemctl status APP_SERVICE

journalctl -u APP_SERVICE

dpkg -l | grep PACKAGE

Correlate changed package versions with the application failure.

🔥 Production Scenario 5 — Package Installed but Command Missing

Check:

dpkg -L PACKAGE

command -v COMMAND

echo $PATH

Possible causes:

  • Executable has a different name
  • Binary is outside PATH
  • Wrong package installed
  • Installation incomplete

🔥 Production Scenario 6 — Package Manager Locked

Another package-management process may already be running.

Inspect processes first: 
ps aux | grep -E 'apt|dpkg'

Do not blindly delete package-manager lock files. First determine whether another legitimate package operation is active.

🔥 Production Scenario 7 — Disk Full During Installation

df -h

df -i

du -xhd1 /var 2>/dev/null

Package management requires working disk space and available inodes.

🧪 Safe Hands-On Lab

Use read-only package inspection commands: 

apt --version

apt search curl

apt show curl

apt-cache policy curl

dpkg -l | head

dpkg -l | grep curl

dpkg -L coreutils | head

dpkg -S /bin/ls 2>/dev/null || true

No package installation is required for this lab.

🧪 Repository Lab

cat /etc/os-release

cat /etc/apt/sources.list 2>/dev/null

ls -la /etc/apt/sources.list.d/

apt-cache policy

Understand which operating system and repositories your machine uses.

🧩 Quick Recall

What does apt update actually do?

It downloads/refreshed package metadata from configured repositories. It does not automatically upgrade all installed packages.

What is the difference between apt and dpkg?

apt is repository-aware and resolves dependencies. dpkg is a lower-level Debian package management tool and package database interface.

Package not found. What are your first checks?

apt update
apt search PACKAGE
apt-cache policy PACKAGE
cat /etc/apt/sources.list
ls /etc/apt/sources.list.d/

🗣️ Strong Interview Answer

“When troubleshooting package installation, I first verify the operating system and configured repositories. I refresh package metadata, check whether the requested package and version are actually available, and inspect dependency requirements. If repository access fails, I troubleshoot DNS, routing and repository configuration separately. In production I also correlate package upgrades with application changes because library or service updates can affect runtime behavior.”
