1. Basic File Operations

pwd
ls -lah

touch file.txt

mkdir directory

cp file.txt copy.txt

mv copy.txt directory/

rm file.txt

rm -r directory

stat FILE

file FILE

2. Reading Files

cat file.txt

less file.txt

head file.txt

head -20 file.txt

tail file.txt

tail -50 file.txt

tail -f application.log

For production logs, less and tail -f are extremely useful.

3. Finding Files

find /etc -name "*.conf"

find /var/log -type f

find /var/log -type f -size +100M

find /tmp -type f -mtime +7

find / -name "application.log" 2>/dev/null

Important find filters

  • -name — filename
  • -type — file type
  • -size — file size
  • -mtime — modification time
  • -user — owner
  • -perm — permissions

4. grep

grep searches text and is one of the most frequently used Linux troubleshooting commands. 

grep "ERROR" app.log

grep -i "error" app.log

grep -n "error" app.log

grep -v "INFO" app.log

grep -R "ERROR" /var/log/

grep -E "ERROR|WARN" app.log

5. Regular Expressions

grep '^ERROR' app.log

grep 'failed$' app.log

grep -E '[0-9]+' file.txt

grep -E 'ERROR|WARNING' app.log

You do not need to memorize every regex feature, but you should understand basic matching.

6. Pipes

A pipe sends stdout from one command into stdin of another. 

COMMAND1 | COMMAND2
Examples: 
ps aux | grep nginx

cat /etc/passwd | grep root

df -h | grep "/"

journalctl | grep -i error

7. Redirection

command > output.txt

command >> output.txt

command 2> error.txt

command > output.txt 2>&1

command < input.txt

Remember: 

0 = stdin
1 = stdout
2 = stderr

8. awk

awk is excellent for extracting columns and structured text. 

awk '{print $1}' file.txt

awk '{print $1,$3}' file.txt

awk -F: '{print $1}' /etc/passwd

df -h | awk '{print $1,$5}'

9. sed

sed is commonly used for text replacement and automation. 

sed 's/old/new/' file.txt

sed 's/old/new/g' file.txt

sed -n '1,10p' file.txt
Example: 
echo "environment=dev" |
sed 's/dev/prod/'

10. cut

cut -d: -f1 /etc/passwd

cut -d, -f1 data.csv

11. sort & uniq

sort file.txt

sort -n numbers.txt

sort -r file.txt

uniq file.txt

sort file.txt | uniq

sort file.txt | uniq -c

12. xargs

xargs converts input into command arguments. 

find /tmp -name "*.tmp" | xargs ls -l
Safer form: 
find /tmp -name "*.tmp" -print0 |
xargs -0 ls -l

13. tee

tee displays output and writes it to a file at the same time. 

echo "hello" | tee file.txt

command | tee output.log

14. Production Log Analysis

Find recent HTTP 500 responses: 

grep " 500 " access.log | tail -50
Find most common client IP addresses: 
awk '{print $1}' access.log |
sort |
uniq -c |
sort -nr |
head
Find largest files: 
find /var -type f -printf '%s %p\n' 2>/dev/null |
sort -nr |
head

15. Useful DevOps Pipelines

Top CPU processes

ps aux --sort=-%cpu | head

Top memory processes

ps aux --sort=-%mem | head

Count errors

grep -i "error" application.log | wc -l

Watch errors live

tail -f application.log |
grep --line-buffered -i error

Find large logs

find /var/log -type f -size +100M

🔥 Production Scenario

Users report HTTP 500 errors after a deployment. The application log contains millions of lines. How would you investigate quickly?

Approach

tail -200 application.log

grep -i "error" application.log |
tail -100

grep "500" access.log |
tail -100

grep -E "ERROR|Exception|Failed" application.log |
tail -100

Then correlate:

  • Timestamp
  • Request ID
  • User request
  • Application error
  • Database/service dependency
  • Recent deployment changes

🔥 Production Scenario 2

The disk is filling rapidly and you need to find which logs are responsible. 

df -h

du -sh /var/log/* |
sort -h

find /var/log -type f -size +100M

lsof +L1
