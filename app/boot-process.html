🚀 Linux Boot Process & systemd

From power-on to a running Linux system, including GRUB, kernel, initramfs, systemd, services, targets and production boot troubleshooting.

⚡ 60-Second Revision

Power ON
   ↓
BIOS / UEFI
   ↓
Boot Device
   ↓
GRUB
   ↓
Linux Kernel
   ↓
initramfs
   ↓
Root Filesystem
   ↓
systemd (PID 1)
   ↓
Targets + Services
   ↓
Login / Application Ready

1. BIOS vs UEFI

BIOS or UEFI performs early hardware initialization and selects a bootable device.

  • BIOS — older firmware model
  • UEFI — modern firmware model
  • UEFI commonly uses an EFI System Partition

Check firmware mode:

ls /sys/firmware/efi

If the directory exists, the system was typically booted using UEFI.

2. GRUB Bootloader

GRUB selects and loads the Linux kernel and its initial RAM filesystem.

Common files:

/etc/default/grub
/boot/grub/
/boot/grub/grub.cfg

Inspect boot directory:

ls -lh /boot

3. Linux Kernel

The kernel initializes core system resources such as:

  • CPU
  • Memory
  • Device drivers
  • Storage
  • Networking
  • Process management

Check running kernel:

uname -r

uname -a

4. initramfs

initramfs is a temporary early userspace filesystem loaded into memory during boot.

It provides tools and drivers required before the real root filesystem can be mounted.

Inspect files:

ls -lh /boot/initrd*

5. Root Filesystem

After required storage drivers and devices are available, Linux mounts the actual root filesystem. 

findmnt /

mount | grep ' on / '

6. PID 1

On most modern Linux distributions, systemd becomes PID 1. 

ps -p 1 -o pid,ppid,comm,args

PID 1 is responsible for bringing up userspace services and managing the system lifecycle.

7. systemd Units

systemd manages several types of units.

  • service
  • socket
  • target
  • timer
  • mount
  • automount
  • path

List loaded units:

systemctl list-units

List services:

systemctl list-units --type=service

8. Managing Services

systemctl status SERVICE_NAME

systemctl start SERVICE_NAME

systemctl stop SERVICE_NAME

systemctl restart SERVICE_NAME

systemctl reload SERVICE_NAME

systemctl enable SERVICE_NAME

systemctl disable SERVICE_NAME

start affects the current runtime. enable controls whether the unit is configured to start automatically through its installation relationships.

9. systemd Targets

Targets group units together and represent system states. 

systemctl get-default

systemctl list-units --type=target

systemctl list-unit-files --type=target

Common targets include:

  • multi-user.target
  • graphical.target
  • rescue.target
  • emergency.target

10. Dependencies

Services may depend on other units. 

systemctl list-dependencies SERVICE_NAME

systemctl cat SERVICE_NAME

Important directives can include:

  • Requires=
  • Wants=
  • After=
  • Before=

Remember: ordering and dependency relationships are related, but they are not exactly the same thing.

11. Boot Performance

systemd-analyze

systemd-analyze blame

systemd-analyze critical-chain

These commands help identify units that contribute to slow startup.

12. Boot Logs

Current boot:

journalctl -b

Kernel messages:

journalctl -k

dmesg

Errors from current boot:

journalctl -b -p err

Failed units:

systemctl --failed

13. Previous Boot

List boots known to the journal:

journalctl --list-boots

Previous boot:

journalctl -b -1

Very useful when a server crashed or rebooted and is healthy again now.

14. Rescue vs Emergency Mode

Rescue Mode

A minimal recovery environment with more services and filesystems available than emergency mode. 

systemctl rescue

Emergency Mode

An even more minimal recovery environment intended for serious boot or filesystem problems. 

systemctl emergency

15. Service Unit Files

Inspect a unit:

systemctl cat SERVICE_NAME

Typical structure:

[Unit]
Description=Example Application
After=network.target

[Service]
ExecStart=/opt/app/start.sh
Restart=on-failure
User=appuser

[Install]
WantedBy=multi-user.target

16. daemon-reload

After creating or modifying systemd unit files: 

systemctl daemon-reload

Then restart or start the affected service if required.

17. Boot-Enabled Services

systemctl list-unit-files --state=enabled

systemctl is-enabled SERVICE_NAME

systemctl is-active SERVICE_NAME

Enabled and active are different concepts. A service may be enabled but currently stopped.

🔥 Production Scenario 1 — Application Missing After Reboot

A server reboot completes successfully, but the application is unavailable. 

systemctl --failed

systemctl status APP_SERVICE

systemctl is-enabled APP_SERVICE

journalctl -u APP_SERVICE -b

ss -tulpn

Check:

  • Did the service start?
  • Is it enabled when it should be?
  • Did a dependency fail?
  • Is the application port listening?
  • Are environment/config files available?

🔥 Production Scenario 2 — Server Boots Very Slowly

systemd-analyze

systemd-analyze blame

systemd-analyze critical-chain

journalctl -b

Find slow services, dependency delays, filesystem waits, network waits or failed startup retries.

🔥 Production Scenario 3 — Service Fails During Boot

systemctl status SERVICE_NAME

journalctl -u SERVICE_NAME -b

systemctl list-dependencies SERVICE_NAME

systemctl cat SERVICE_NAME

Investigate:

  • Dependency order
  • Missing files
  • Permissions
  • Environment variables
  • Network/storage readiness
  • Invalid ExecStart

🔥 Production Scenario 4 — Filesystem Prevents Normal Boot

Possible investigation points:

journalctl -b

systemctl --failed

findmnt

cat /etc/fstab

lsblk -f

A bad or unavailable filesystem entry can cause boot delays or failures, depending on configuration.

🔥 Production Scenario 5 — Server Rebooted Unexpectedly

After the server comes back:

who -b

uptime

journalctl --list-boots

journalctl -b -1

journalctl -k -b -1

Correlate previous-boot logs with kernel events, OOM messages, hardware/storage errors and application events.

🧩 Quick Recall

What is the Linux boot flow?

BIOS/UEFI → bootloader/GRUB → kernel → initramfs → root filesystem → systemd/PID 1 → targets/services → login/application.

What is the difference between start and enable?

Start changes the current service runtime state. Enable configures the unit's startup relationships for future boots or target activation.

Server rebooted and app is down. What are your first checks?

systemctl --failed
systemctl status APP_SERVICE
journalctl -u APP_SERVICE -b
systemctl is-enabled APP_SERVICE
ss -tulpn

🗣️ Strong Interview Answer

“When Linux powers on, BIOS or UEFI initializes the hardware and selects a boot device. The bootloader, commonly GRUB, loads the Linux kernel and initramfs. The kernel initializes hardware and core resources, then the real root filesystem becomes available. On most modern distributions, systemd starts as PID 1 and brings up the required targets, services and dependencies until the system reaches its configured operating state.”
