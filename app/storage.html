💾 Linux Storage & Filesystems

Disks, partitions, filesystems, mounts, inodes, LVM, swap, RAID/NFS basics and production storage troubleshooting.

1. Block Devices

Storage devices appear as block devices. 

lsblk

lsblk -f

lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS

Common device names:

/dev/sda
/dev/sdb
/dev/nvme0n1

2. Disk vs Partition

A disk is the complete storage device. A partition is a logical section of that disk.

Example: 
/dev/sda      Disk
/dev/sda1     Partition
/dev/sda2     Partition

Inspect safely:

lsblk

cat /proc/partitions

3. MBR vs GPT

  • MBR — older partitioning scheme
  • GPT — modern partitioning scheme
  • GPT supports larger disks and more flexible partition layouts
  • GPT is commonly used with UEFI systems

4. Filesystems

A filesystem organizes files and directories on storage.

Common Linux filesystems include:
  • ext4
  • XFS
  • Btrfs
  • tmpfs
Inspect: 
lsblk -f

findmnt

df -T

5. Mounting

A filesystem becomes accessible through a mount point.

Inspect mounts: 
mount

findmnt

findmnt /

findmnt /home

Concept:

Device → Filesystem → Mount Point → Files

6. /etc/fstab

The filesystem table describes filesystems that should be mounted according to system configuration. 

cat /etc/fstab
Typical fields: 
DEVICE  MOUNT_POINT  TYPE  OPTIONS  DUMP  PASS

UUIDs are often preferred over unstable device names.

Inspect UUIDs: 
blkid

lsblk -f

7. df vs du

df

Shows filesystem-level usage:

df -h

du

Shows file/directory usage:

du -sh /var

du -sh /var/* 2>/dev/null

du -xhd1 /var 2>/dev/null

This difference is extremely important in production troubleshooting.

8. Inodes

An inode stores filesystem metadata about a file. A filesystem can run out of inodes even while space remains.

Check: 
df -i
Symptoms can include: 
No space left on device
even when: 
df -h
shows free capacity.

9. Deleted Files Still Consuming Space

Deleting a file does not immediately release its blocks if a running process still has that file open.

Check: 
lsof +L1

This is a classic reason why df and du can disagree.

10. Disk Usage Investigation

df -h

du -xhd1 / 2>/dev/null

du -xhd1 /var 2>/dev/null

find /var/log -type f -size +100M 2>/dev/null

lsof +L1

Start broad, identify the affected filesystem, then narrow down to directories and files.

11. Swap

Swap provides disk-backed virtual memory that can be used under memory pressure.

Inspect: 
swapon --show

free -h

cat /proc/swaps

Swap is much slower than RAM and should not be treated as a replacement for sufficient memory.

12. LVM Overview

Logical Volume Manager adds a flexible abstraction layer over storage. 

Disk / Partition
      ↓
Physical Volume (PV)
      ↓
Volume Group (VG)
      ↓
Logical Volume (LV)
      ↓
Filesystem
      ↓
Mount Point
Inspect safely: 
pvs

vgs

lvs

13. Why LVM Is Useful

  • Flexible logical volumes
  • Storage can be pooled into volume groups
  • Volumes can often be extended
  • Useful for server storage management
  • Supports snapshot-related workflows

Actual resize operations should be practiced only in a disposable lab environment.

14. RAID Basics

RAID combines multiple storage devices for performance, redundancy or both.

  • RAID 0 — striping, no redundancy
  • RAID 1 — mirroring
  • RAID 5 — distributed parity
  • RAID 10 — mirror + stripe combination

RAID is not a backup.

15. NFS Basics

NFS allows filesystems to be shared over a network.

Inspect NFS mounts: 
findmnt -t nfs,nfs4

mount | grep nfs

Production NFS issues can involve network connectivity, DNS, server availability, permissions and stale mounts.

16. Filesystem Information

df -T

lsblk -f

findmnt

stat -f /

These commands help identify filesystem type, device and mount relationships.

17. Mount Options

Inspect:

findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS
Common concepts include:
  • rw / ro
  • noexec
  • nosuid
  • nodev
  • defaults

Mount options can affect application behavior and security.

🔥 Production Scenario 1 — Disk 100% Full

df -h

du -xhd1 / 2>/dev/null

du -xhd1 /var 2>/dev/null

find /var/log -type f -size +100M 2>/dev/null

lsof +L1

Investigate:

  • Growing application logs
  • Temporary files
  • Database data
  • Container data
  • Backup files
  • Deleted-open files

🔥 Production Scenario 2 — No Space Left but Disk Has Space

First check:

df -h

df -i

Possible reasons:

  • Inode exhaustion
  • Another filesystem is full
  • Application-specific quota or limit
  • Deleted-open file situation

🔥 Production Scenario 3 — df and du Do Not Match

df -h

du -xsh /path

lsof +L1

A common cause is a deleted file that is still held open by a process.

🔥 Production Scenario 4 — Mount Missing After Reboot

findmnt

lsblk -f

cat /etc/fstab

systemctl --failed

journalctl -b | grep -i mount

Check:

  • Correct UUID/device
  • Filesystem type
  • Mount point exists
  • Storage is available
  • fstab syntax/options
  • Network storage dependencies

🔥 Production Scenario 5 — Filesystem Became Read-Only

Check:

findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS

mount

dmesg | tail -100

journalctl -k -n 100

A filesystem may become read-only due to configuration or underlying filesystem/storage errors. Kernel logs are important here.

🔥 Production Scenario 6 — NFS Application Hangs

findmnt -t nfs,nfs4

mount | grep nfs

ping NFS_SERVER

getent hosts NFS_SERVER

ss -tan

Investigate:

  • NFS server availability
  • Network path
  • DNS resolution
  • Mount options
  • Storage server health

🧪 Safe Hands-On Lab

Safety: Do not run mkfs, fdisk, parted or destructive storage commands against your laptop's real disks.

Use read-only inspection commands:

lsblk

lsblk -f

df -h

df -T

df -i

findmnt

findmnt /

blkid

free -h

swapon --show

🧪 Disk Usage Lab

mkdir -p ~/storage-lab

cd ~/storage-lab

dd if=/dev/zero of=testfile bs=1M count=10 status=none

ls -lh testfile

du -h testfile

df -h .

stat testfile

rm testfile

This creates only a small 10 MB regular file inside your home filesystem.

🧪 Inode Lab

mkdir -p ~/storage-lab/inodes

cd ~/storage-lab/inodes

touch file{1..100}

ls | wc -l

df -i .

rm -f file*

This helps demonstrate that every file consumes an inode.

🧩 Quick Recall

What is the storage flow?

Disk → Partition → Filesystem → Mount Point → Files/Application Data

df has free space but writes fail with No space left. What should you check?

df -h
df -i
findmnt
lsof +L1

Why might df and du disagree?

One classic cause is a deleted file that is still open by a running process. Filesystem-level allocation remains until the process closes the file descriptor.

🗣️ Strong Interview Answer

“When troubleshooting Linux storage, I first identify the affected filesystem using df and lsblk. I then check filesystem type and mounts with findmnt, inspect directory usage with du, verify inode availability with df -i, and check for deleted files still held open using lsof +L1. For reboot-related mount problems I also verify /etc/fstab, UUIDs, storage availability and boot logs.”
