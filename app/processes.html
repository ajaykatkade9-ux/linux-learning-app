⚙️ Processes & Job Control

Processes, PID/PPID, signals, jobs, priorities, zombies, orphans and production troubleshooting.

A program is code stored on disk. A process is a running instance of that program.

1. PID and PPID

Every process has a Process ID and usually a parent process.

echo $$

ps -ef

ps -o pid,ppid,cmd

pstree -p
  • PID — Process ID
  • PPID — Parent Process ID

2. Inspect Processes

ps aux

ps -ef

top

pgrep nginx

pgrep -a ssh

pstree

Use ps for a snapshot and top for live monitoring.

3. Process States

R = Running / Runnable
S = Interruptible Sleep
D = Uninterruptible Sleep
T = Stopped
Z = Zombie

Inspect process states:

ps aux

ps -eo pid,ppid,state,cmd

4. Signals

Signals allow the operating system and users to communicate with processes.

kill -l
  • SIGTERM (15) — graceful termination request
  • SIGKILL (9) — immediate forced termination
  • SIGHUP (1) — often used to reload configuration
  • SIGSTOP — stop a process
  • SIGCONT — continue a stopped process

5. SIGTERM vs SIGKILL

Graceful termination:

kill PID

kill -15 PID

Force termination:

kill -9 PID

Production rule: use SIGTERM first whenever possible. SIGKILL should normally be a last resort.

6. Process Control by Name

pkill nginx

pkill -TERM nginx

killall nginx

Be careful when terminating processes by name on production systems.

7. Foreground and Background Jobs

Start a process:

sleep 300

Suspend it:

Ctrl + Z

Inspect jobs:

jobs

Move to background:

bg

Return to foreground:

fg

Start directly in the background:

sleep 300 &

8. nohup

nohup can keep a process running after the terminal session ends. 

nohup ./script.sh > app.log 2>&1 &

Verify:

ps aux | grep script.sh

9. nice and renice

Linux uses nice values to influence CPU scheduling priority. 

-20  Higher scheduling priority

0    Default

19   Lower scheduling priority

Start a process with a nice value:

nice -n 10 COMMAND

Change an existing process:

renice 10 -p PID

10. Zombie Processes

A zombie is a child process that has exited but whose parent has not yet collected its exit status. 

ps aux | awk '$8 ~ /^Z/'

ps -eo pid,ppid,state,cmd

The real problem usually needs to be fixed in the parent process.

11. Orphan Processes

An orphan is a process whose parent exits while the child continues running. 

pstree -p

ps -o pid,ppid,cmd

12. Open Files and Sockets

lsof -p PID

lsof /path/to/file

lsof -i

This is extremely useful when troubleshooting processes, network sockets and deleted files that still consume disk space.

13. CPU and Memory Usage

Top CPU-consuming processes:

ps aux --sort=-%cpu | head

Top memory-consuming processes:

ps aux --sort=-%mem | head

Live monitoring:

top

System overview:

uptime
vmstat 1
free -h

14. Process Environment

Environment variables:

tr '\0' '\n' < /proc/PID/environ

Command line:

cat /proc/PID/cmdline | tr '\0' ' '

Working directory:

readlink /proc/PID/cwd

15. /proc Process Information

Linux exposes process information under:

/proc/PID/

Useful locations:

/proc/PID/status
/proc/PID/cmdline
/proc/PID/environ
/proc/PID/fd

Example:

cat /proc/1/status

🔥 Production Scenario 1 — High CPU

Users report that the application is slow and CPU usage is high. 

uptime

nproc

top

ps aux --sort=-%cpu | head

vmstat 1

Investigate:

  • Which process is consuming CPU?
  • How many CPU cores are available?
  • Is the load expected?
  • Is there high I/O wait?
  • Was there a recent deployment?
  • Do application logs show loops or errors?

🔥 Production Scenario 2 — Process Keeps Restarting

systemctl status SERVICE_NAME

journalctl -u SERVICE_NAME

ps aux | grep PROCESS_NAME

systemctl show SERVICE_NAME --property=Restart

Possible causes:

  • Application crash
  • Missing environment variables
  • Permission problems
  • Dependency failures
  • OOM termination
  • Incorrect restart policy

🔥 Production Scenario 3 — Process Will Not Stop

First request graceful termination:

kill -15 PID

Check whether the process still exists:

ps -p PID

top -p PID

If graceful shutdown fails and forced termination is truly required:

kill -9 PID

Afterward, investigate why the process ignored or failed to complete graceful shutdown instead of making SIGKILL the normal solution.

🔥 Production Scenario 4 — Deleted File Still Uses Disk

A huge log file was deleted, but disk space was not released. 

lsof +L1

A running process may still have the deleted file open. The file's disk space is released only after the open file descriptor is closed.

🔥 Production Scenario 5 — Process in D State

A process appears stuck in uninterruptible sleep. 

ps -eo pid,ppid,state,wchan:30,cmd

vmstat 1

dmesg | tail -50

D state commonly indicates the process is waiting on kernel I/O, such as disk, storage or network filesystem operations.

Find your shell PID:

🗣️ Strong Interview Answer

“When troubleshooting a Linux process issue, I first identify whether the problem is CPU, memory, I/O, application failure or process state. I identify the relevant PID, inspect its resource usage, logs, parent-child relationships, open files, environment and /proc data. For termination I prefer SIGTERM so the application has a chance to clean up gracefully, and I use SIGKILL only when necessary.”
