🐧 Linux Foundations

Foundation knowledge required before moving into administration, containers, cloud, Kubernetes and production troubleshooting.

⚡ 60-Second Revision

Linux is an operating system built around the Linux kernel. Applications run in user space while the kernel manages CPU, memory, processes, devices, filesystems and networking.

Remember:

Hardware
   ↓
Linux Kernel
   ↓
System Libraries
   ↓
Shell / Services
   ↓
Applications / Users

1. Linux Architecture

  • Hardware — CPU, RAM, disks and network devices
  • Kernel — manages hardware and system resources
  • System Libraries — allow applications to interact with the kernel
  • Shell — command-line interface
  • Applications — programs running in user space

2. Kernel Space vs User Space

Kernel Space

  • Highly privileged
  • Controls hardware
  • Memory management
  • Process scheduling
  • Networking
  • Filesystems

User Space

  • Applications
  • Shells
  • Utilities
  • Most services

3. Linux Distributions

A Linux distribution combines the Linux kernel with package managers, utilities, libraries and system configuration.

  • Ubuntu
  • Debian
  • Red Hat Enterprise Linux
  • Rocky Linux
  • AlmaLinux
  • Amazon Linux

DevOps engineers should understand both Debian/Ubuntu and RHEL-style systems.

4. Filesystem Hierarchy

/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── media
├── mnt
├── opt
├── proc
├── root
├── run
├── srv
├── sys
├── tmp
├── usr
└── var
  • /etc — system configuration
  • /var — logs and changing application data
  • /home — normal user home directories
  • /root — root user's home
  • /tmp — temporary files
  • /opt — optional third-party software
  • /proc — process and kernel information
  • /sys — kernel/device information
  • /dev — device files
  • /boot — bootloader and kernel files

5. Absolute vs Relative Paths

Absolute path:

/var/log/nginx/access.log

Relative path:

logs/application.log

Absolute paths start from /. Relative paths start from your current directory.

6. Linux File Types

ls -l

The first character identifies the file type:

-  Regular file

d  Directory

l  Symbolic link

c  Character device

b  Block device

p  Named pipe

s  Socket

7. Hard Links vs Symbolic Links

Hard Link

  • References the same inode
  • Normally cannot cross filesystems
  • Still works if original filename is removed

Symbolic Link

  • Stores a path to another file
  • Can cross filesystems
  • Can become broken if target disappears
ln file1 hardlink

ln -s file1 symlink

🔥 Production Scenario

An application configuration references: 

./config/app.conf

The application works when started manually but fails when started by systemd. Why?

Think About

  • Relative paths
  • Working directory
  • Runtime user
  • Permissions
  • Environment differences

Investigation

pwd

systemctl cat SERVICE_NAME

systemctl show SERVICE_NAME \
  --property=WorkingDirectory

journalctl -u SERVICE_NAME

Production services should generally use predictable configuration and absolute paths where appropriate.

🗣️ Interview Explanation

A strong short explanation:

“Linux is an operating system built around the Linux kernel. The kernel operates in privileged kernel space and manages CPU, memory, devices, filesystems, networking and processes. Applications normally run in user space and communicate with the kernel through system calls. Linux distributions package the kernel with utilities, libraries, package managers and administration tools.”
